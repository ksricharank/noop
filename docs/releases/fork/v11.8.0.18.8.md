# 11.8.0.18.8 (build 409)

Three faults from the 18.7 install, one of them a coach error that blamed the network for our own
cancellation.

## The sparklines, take two — and this time as a switch

18.7 removed the hover trackers that could never fire on a touch device. The maintainer installed it
and reported the two grids still scroll badly.

What remains in every sparkline is a **`GeometryReader`**. It participates in layout on every pass
and propagates size upward, and Sleep's Night detail holds **seven** of them inside a scrolling
`LazyVGrid`.

It was never needed. The only thing read from it is `geo.size`, and every call site already pins the
frame — `StatTile` uses `.frame(height: 22)`. A `Canvas` at that same fixed size draws the identical
line: same polyline, same area wash, same head dot, same gradient sampling.

**Shipped as Settings → Appearance → "Detailed sparklines", not as a silent default.** The cause of
this lag was wrong six times before the maintainer bisected it on-device; a claim from this side has
not been worth much. A toggle settles it in about five seconds, on the tab where it matters, without
another round-trip — and if the Canvas path is not the answer, "leave them off" is still an
available answer that does not cost the cards entirely.

Read through `@AppStorage`, so flipping it re-renders every sparkline live. The key is stored
**inverted** (`noop.richSparklines`): a default-ON preference over a `Bool` that reads `false` when
unset defaults the wrong way, and `SparklinePrefsTests` pins that.

ON also restores the pointer tooltip, which is the honest reason to keep the old path rather than
delete it — an iPad or a Mac can actually reach it.

## Ask the Coach reported a network error that was ours

From Recap, Sleep or Trends the chat opened and immediately showed:

> Network problem: cancelled. The coach is the only feature that needs the internet.

There was no network problem. `CoachView` consumed the handoff in a
`.task(id: coach.pendingPrompt)`, and **`.task(id:)` cancels and restarts its body whenever the id
changes** — while the body's first statement was `coach.pendingPrompt = nil`.

So the task cancelled the very request it was about to `await`. That surfaced as
`URLError.cancelled` → `.network("cancelled")` → a message blaming the internet.

It only appeared once 18.7's tab summaries began seeding `pendingPrompt`. The original caller — the
Today launcher — sets it and pushes in one gesture, racing past the window. That is exactly why the
maintainer could watch every tab summary generate correctly and this one path fail, and why "the
rest of the LLM features work fine" was the right observation.

Now an `onChangeCompat` (clearing no longer triggers a cancellation) plus a plain `.task` for the
case where the prompt was already set before the view appeared — which no `onChange` would ever see,
and which is every tab handoff.

## Integration was there, and unfindable

It shipped as a row inside the **backup** card, inside the **collapsed Advanced** group. The
maintainer looked, reasonably, at the Backup & Sync screen and saw nothing.

It now has its own always-visible section beside the everyday settings, and the row reads "Set up
the daily digest file…" until a folder is chosen. Backup & Sync stays under Advanced: it is
configured once and then forgotten, which is the distinction that should have decided this the first
time — a daily surface does not belong behind a disclosure.

## Verification

Both app targets compile; the full macOS suite runs with only the two pre-existing
`SkinTempAbsoluteDisplay` / `SleepCarriedStamp` failures already confirmed on a clean v11.8.0
worktree.

Three new tests pin the sparkline preference: the default-off-over-an-inverted-key semantics, the
toggle in both directions, and the literal key string (which is the `.noopbak` contract).

**The renderer swap itself is visual and cannot be confirmed by compiling.** That is what the toggle
is for.

## What the next build must check

- **Scroll Sleep's Night detail and Trends' Daily signals with the toggle OFF.** Then turn it ON and
  scroll the same two pages. If OFF is smooth and ON is not, the `GeometryReader` was the cost and
  the default is right. If both are slow, the cost is the sheer number of drawn views and hiding the
  two cards is the honest answer.
- **Ask the Coach from each of Recap, Sleep and Trends** — each should open mid-conversation with
  that tab's summary and no error banner.
- **Settings shows Integration without expanding Advanced.**
