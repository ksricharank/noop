# Fork build 10.6.0.14.2

**Base:** upstream [`v10.6.0`](https://github.com/ryanbr/noop/releases/tag/v10.6.0) staging line ·
**Build:** 266 · **Date:** 28 August 2026 · **Platform:** iOS (sideload)

Second fix within feature-set 14. Context: iOS gives a suspended app no unlock signal, so under the
duty cycle (`-1`) a long-idle unlock shows the frozen average until the next sync wake or an
app-open (confirmed in the 260828-1425 log: the "stuck 90" unlock left no trace — the app was
asleep; morning unlocks worked only because backlog churn kept the process awake). This build makes
that physics honest and durable in every mode. All on `feature/locked-stream-duty-cycle`.

**1. The tilde marks LIVE beats.** `ContentState` gains `live: Bool?` (nil default — older
activities decode as not-live). The HR stat shows `~72` for a live beat and the plain number for a
window average / frozen value — deliberately that way round: when the phone locks and pushes stop
reaching the card, whatever it holds is by definition not live, and the plain form it is left with
stays honest with no repaint needed. Banner, island expanded-leading, and compact-trailing all use
one formatter; the minimal slot keeps the bare number (it clips rather than shrinks — a tilde would
cost a workout HR's third digit).

**2. `+N` mode: the lock-edge average.** `+N` pushed its first locked average a full N minutes
after the lock, holding the last raw live beat until then (reported as "+5 just freezes the last HR
value" — it was the `-1` lock-edge bug's twin, never fixed for `+N`). The first locked tick now
pushes the window average immediately; the sample buffer is fed on every tick, so it is a true
N-minute average from second one. `+N` locked pushes also drop their staleDate (same iOS 26
removal hazard the `.14.1` fix covered for `-1`).

**3. The 8 h lease renewal.** iOS ends every Live Activity ~8 hours after creation (updates never
extend it), and no background start can bring it back — a card born in the morning died
mid-afternoon. `update()` now ends + re-requests an activity older than 6.5 h when the app is
foreground-active: an invisible blink on an app open instead of a disappearance. Birth time is
tracked at request and approximated at adoption; a rare-event log line marks each renewal.

**4. An honest #927 log line.** "Continuous HRV: overnight window opened; arming…" fired on ANY
combined-want rising edge — under the duty cycle that is every unlock, so midday copies of
"overnight window opened" sent the 260828-1425 analysis down the wrong path (the #1635
assert-only-what-you-observed class). Both edges now name exactly what they saw: "realtime want
flipped ON/OFF", with the candidate causes listed, none claimed.

Verified: both apps compiled; `LockedStreamPolicyTests` + `DeviceLockStateTests` pass.

## Where the unlock story now stands (`-1` vs `+N`)

- `-1` (duty cycle): locked card = plain averages, repainted per sync + both lock/unlock edges;
  after a long-idle unlock it goes live at the next sync wake or instantly on app-open (iOS
  physics; a tap-to-go-live island intent is the designed follow-up if wanted). Battery: hr wakes
  ≈ 0 while locked.
- `+N`: stream always on — instantly live at every unlock, `~` appears immediately; locked card
  shows true N-minute averages from the first second of the lock. Battery: the full ~5.3k wakes/h
  around the clock (the pre-fork bill).
- The user is A/B-ing the two modes against `MetricKit bg=` and the iOS battery screen — the
  `260828-1425` log carried the first MetricKit line: **08-27 bg=1318m (~22 h)**, the baseline.
