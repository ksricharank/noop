# 12.0.0.19.6 (build 442) — 261007

One feature: `feature/store-concurrent-reads`, the fix for the open systemic item every log since
19.0 has carried (store-actor read serialization). Built as its OWN deprecable branch at the
maintainer's instruction — drop it from FEATURES to ship without it; nothing stacks on top of it.
Deliberately NOT filed upstream (maintainer call: clean separation of concerns).

## The mechanism

Every store read arrived through the blocking `syncRead`, which holds the WhoopStore actor's serial
executor until the rows are back. The #755 `DatabasePool` can serve reads in parallel at the SQLite
layer; the actor above it re-serialized them into one line. Convicted costs, from the field:

- 261005: one 21-night pass read held the actor 104 s; two ~130 s Today loads queued behind it.
- 261006: Health sync avgSyncMs 139,634 — reads 132 s of it, mostly queue wait.
- 261007: retro-scan queued 814 s for 125 ms of replay; a Today screen took 30.3 s to show numbers
  that had been on disk since 09:01:34 (the "I came back after 10 minutes and it was stale" report —
  the data was never late, the SCREEN's read was queued behind the relaunch's own pass).

`concurrentRead` is the async twin: GRDB's async `read` dispatches the closure to a pooled reader
connection and the await genuinely suspends, so the actor is FREE while SQLite works. All 90 async
read call sites converted; `syncRead` survives only for the synchronous export path
(`tableRowEstimates`). Writes untouched — `syncWrite` still blocks the actor, so write ordering and
every transaction are byte-identical.

## The risk, and how it was discharged

Suspending mid-method makes the actor reentrant where it previously was not. Audit of all 90 sites:
each is a single self-contained statement whose closure captures only value parameters; no actor
state is read or written across any suspension (the one offender shape found — `rawFrames` handing
a non-Sendable GRDB `Row` across the hop — now passes the `Data` blob instead). Cross-call
interleaving already existed (every store call is its own await); this only extends it INTO a read's
await, where nothing holds state. Reads were already independent WAL snapshots.

The perf ledger (`reads=`/`maxRead=` strap-log line — the instrument every slow-store episode was
diagnosed with) accrues identically through the new funnel; its semantics shift from "SQL time on
the actor" to "wall-to-caller including reader-pool queue wait", which is the number the line exists
to explain. Note for log-reading: `maxRead` can now also reflect reader-pool contention, not only
one statement's cost.

## Verification

- `ConcurrentReadTests` (3): overlap-shaped pins, never timing ratios — the actor answers, and a
  quick read completes, while a deliberately slow read (recursive-CTE through the production funnel)
  is still in flight; the perf ledger keeps counting. All three fail deterministically under the
  old blocking helper.
- WhoopStore package suite 638/638 green.
- Both app targets compile (no app-layer diff at all — the store's public API was already async).
- Full StrandTests: only the pre-existing known-failing set (IntelligenceRRSourceTests family +
  the two timezone-sensitive caption tests from 19.0's notes); zero new failures.

## What the next log must show

- `screenLoad screen=today ms=` in the low seconds (ideally hundreds of ms) even when a pass is
  running — the 30,346 ms / 34,132 ms / 35,124 ms loads of 261007 are the before.
- Health sync `avgSyncMs` back toward seconds; retro-scan `maxWait` collapsing toward its `maxReplay`.
- `analyzeRecent store sql reads=` roughly UNCHANGED (the pass itself is still sequential — its own
  reads were never the queue victims). A pass that got dramatically *slower* would suggest reader-pool
  starvation and is the deprecation signal.
- No new correctness oddities on scored values: charge/sleep/effort figures byte-identical to what a
  440/441 pass produced from the same data.

## Deprecation procedure (if it doesn't work)

Remove `feature/store-concurrent-reads` from FEATURES on this branch, re-cut, bump the counter.
The branch rewrites only `Packages/WhoopStore`; no other feature references it.
