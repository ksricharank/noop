# Fork release 10.6.0.14.10 (build 272)

The maintainer's same-day review of 10.6.0.14.9 ("I tried the app and I want the following
changes"). Two commits on `feature/targets-widgets` + one new branch `feature/breathe-automation`
(stacked on it — same re-homing chain as the 260829 trio, now four deep).

## The targets trio is now Effort · Cal · Sleep — HR is gone from every targets surface

Both Lock-Screen widgets, the home widgets, the Live Activity (banner + island, compact and
minimal slots included) and the Today synthesis strip now carry:

- **Effort n/t** — today's effort over its target, on the user's display scale ("3.2/10.7").
  Numerator is `LiveTargets.effortTodayStored` (today's row, never the carried anchor day's).
- **Cal n/t, TOTAL calories** — the raw whole-day HR estimate over `DailyTargets.dayKcalTarget`
  = a full day of resting metabolism + the prescribed session through the Keytel model, rounded
  to 25. A REST day's target is honestly the resting day alone. (The 14.8 exercise-only framing —
  day estimate minus resting accrual — is retired with HISTORY notes; the maintainer wants the
  mainstream-tracker total.)
- **Sleep** — unchanged ("8h05").

Spacing: banner stats dropped one type step (.headline) with shrink-to-fit so three n/t pairs hold
one row; the home medium widget dropped to 22pt; systemSmall keeps label/value rows. The compact
island slot carries today's effort alone (the pair clips); minimal likewise, red for identity.
Retired with the HR column: `burstAvgHr` (lived one build), the breathe-cue LEVEL read
(`StressOnsetDetector.breatheCue`, `AppModel.breatheCue`, the red-digit tint, `breatheEdge`) —
all HISTORY-noted. ContentState/WidgetSnapshot keep the dead keys declared for decode compat.

## The HRV dip now reaches the wrist + screen (feature/breathe-automation)

Automations → Haptic coaching → Stress check-ins: the existing auto-nudge (strap buzz + in-app
card on a fresh, non-exercise HRV dip while still) gains a **screen notification** — "Take a deep
breath" — via `BreatheNotifier` (IllnessNotifier idiom; permission asked at toggle time; fixed id
so nudges replace, not stack). New "Screen notification" sub-toggle, default ON beneath the two
existing opt-ins. The detector's own gates (sustain, de-dup, rate limit, exercise gate, quiet
hours 22:00–07:00) all still apply.

**The physics, stated plainly (the maintainer asked):** detection needs live R-R. With the
island-less default mode (Continuous HRV overnight-only) there is NO daytime stream, so no daytime
buzzes — and overnight the "Respect quiet hours" sub-toggle (22:00–07:00) suppresses what the
stream could detect. In the default mode this automation is therefore effectively armed-but-idle;
it works whenever the stream actually runs (richer modes, manual realtime). A burst-retrospective
variant (detect the dip in offloaded R-R, nudge ~15 min late) is the open follow-up if wanted.

## Synthesis: Heart bullet reads the heart's trajectory

The prompt's Heart bullet no longer states a this-minute verdict (calm/STRESSED/not judgeable —
retired with the red digits). It now reads the heart's OVERALL state: latest RHR + HRV against
personal baselines (the z-score lines are explained to the model), multi-day drift, watchouts
(climbing RHR, sagging HRV, elevated respiration), and the overall prescription. Activity bullet
cites effort AND total calories n/t; Rest & sleep unchanged. `dailyTargetsBlock` lost its Heart
line + currentBpm/breathe params; tests re-pinned.
