## 1. Every notification buzzes the strap

"The app doesn't buzz the device for all notifications."

- Before: only the morning brief, pace checks, water reminders, stress check-ins and (19.35) high-NSS
  alerts buzzed. Effort target reached, illness watch, the coach brief, strap battery alerts and the
  wind-down reminder posted silently.
- `NotificationBuzz.posted(cue)` (new, `Strand/System/StrapBuzzPrefs.swift`) is called right after each
  of those posts; `AppModel` installs the handler (`buzzForNudgeIfEnabled`), so each has its own switch
  under Automations › Buzz my wrist (default on, under the master like the others).
- Wind-down is pre-scheduled, so iOS shows it without waking NOOP. Each sync now checks delivered
  notifications for it and buzzes once per delivery (none if over 30 min old). Log:
  `Automation: wind-down buzz (delivered N min ago)`.
- Not buzzed: the smart-alarm wake mirror and alarm backup (the strap's own alarm is the buzz there).

## 2. The buzz is configurable

"How configurable is the buzz? … strength, number of buzzes, any other possible patterns."

- The 5/MG buzz is `[0x01][8 waveform effect slots][loop u16][overallLoop]`; NOOP has always sent effects
  47, 152 (hardware-confirmed). Read as a DRV2605-style sequencer, 47 = "buzz 100%" and 152 = a 240 ms
  pause, so strength is already at maximum: the levers are pulse length and repeats. That reading is a
  hypothesis; only Standard is confirmed.
- Automations › Buzz my wrist: **Buzz style** (Standard; Long = 15, 750 ms alert; Longest = 16, 1 s alert;
  Pulsing = 52 — the last three marked experimental), **Buzzes per notification** (1–8, default 3, the
  long-standing count), and **Test buzz**. Style applies to every 5/MG buzz; the count to the
  notification buzz (`buzzStrapOnce`).
- `MaverickHaptics.notificationBuzz(loops:effects:)`; the default bytes are unchanged (test pins it).
  Log: `Buzz: one-shot written (5/MG maverick buzz ×N style …)`.

## 3. Each day starts with 6 cups of water counted

"I don't always remember to drink — I want the 0 water to be some nonzero default (6?)."

- `HydrationDayStart`: each local day opens with ONE ordinary entry of N cups (default **6**, 0–12,
  Automations › Water reminders › "Cups counted each morning"), logged through `logHydration` on the first
  sync or screen load of the day, so Today, reminders, recap and widget all read the same total. It can
  be edited or deleted like any entry; water is read-only to Apple Health, so nothing is exported.
- Why 6: the drinking baseline is 12 cups; drinks that go unlogged (coffee, tea, water with meals) are
  plausibly about half of that.
