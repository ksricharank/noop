# Fork release 10.6.0.14.5 (build 267)

Three changes, three new feature branches, one build — driven by the 260829-0953 and 260829-2144
logs and an interactive design session. Numbered as a MINOR release although the FEATURES set grew:
major **15** is reserved for the planned refactor of the fork's features into a simpler list, to be
done only after this build verifies (the user's explicit sequencing).

All three branches are deliberately based on the `release-10614-2` assembly rather than
`upstream/main` — `three-pillar-card` additionally stacks on `island-disconnect-hold` (both edit the
controller/widget). This avoids re-fighting the LiveActivityController merge conflicts for one
night; the v15 refactor re-homes everything properly. The release branch `release-10614-5` is
therefore an EXTENSION of `release-10614-2` (same underlying feature tips), not a from-scratch
rebuild.

## 1. `feature/rescore-lock-convergence` — the re-score treadmill fix (battery)

The two 260829 logs caught the deferred-settle machinery running as a treadmill: with the phone
locked and the +5 locked sync landing rows every ~5 minutes, every `BGProcessingTask` settle
completed into `debt NOT settled` (#1681 — a newer mark always arrives mid-pass), every deferral
re-armed the task, and it fired again roughly every half hour. **38 full 15-night passes in one
day, ~2 hours of I/O-throttled wall time (one pass ran 54 minutes), none visible on a locked
screen — and the CPU pressure got the process killed twice** (13:37/13:47 background restores in
the 2144 log; those kills are also island-death fuel, since a dead process pushes nothing).

The task handler now decides before spending anything (`RescoreBackgroundPolicy.settleDecision`,
pure + pinned):
- unlocked settles always run (the original #1538 escalation is untouched);
- a settle fired inside the sleep window re-arms for just past the window's end;
- a locked settle runs at most once per 3 h — the one that paints the widget after the window
  ends — and the skip is one strap-log line (`re-score: background settle skipped — …`).

`schedule(earliestIn:)` keeps the pacing when the offload deferral path re-submits
(cancel-and-resubmit would otherwise erase it). The next unlock still settles immediately through
the untouched foreground path.

**What the next log must show:** `re-score: background settle skipped` lines where the treadmill
used to be; locked-hours `re-score: done` passes at ≤ a few per day; session CPU well under the
1899 s / 1288 s of the two motivating logs.

## 2. `feature/island-disconnect-hold` — the card survives every link drop

Both island deaths reported on 260829 shared one mechanism: a link drop ended the Live Activity
unless the -1 duty cycle had the phone locked, and the end was one-way (iOS forbids background
starts). Taking the strap off to charge killed the island for the whole charge; a transient timeout
with the phone locked in a pocket (10:17–13:08 in the 2144 log) killed it until the next app open.

A drop now NEVER ends the card. `LiveActivityPresentationPolicy` answers a disconnect with
`holdIfShowing`; the drop edge repaints once (`noteDisconnected`) with only the honesty bits
changed — `live` off (plain number, no tilde) and `bonded` off, which greys the widget's identity
icons as the not-connected cue (the minimal slot keeps its red: demoted next to another app's
activity, the tint is its only identity). The reconnect edge bypasses the locked spacing
(`bondedEdge`, twin of the lock edge) so the cue clears on the first tick of the restored link.
The card comes down only via the toggle, the sleep window, or an explicit end.
`LockedStreamPolicy.holdOnDisconnect` is retired with a HISTORY note.

**Verify on phone:** take the strap off and charge it — banner + island stay, icons grey, values
hold plain; re-wear → tilde and red icon return within a beat (unlocked) or immediately on the
first locked tick.

## 3. `feature/three-pillar-card` — the three-pillar card + synthesis reorientation

The card and the coach synthesis reorient around three pillars — rest & sleep, breathing & heart
rate, activity & exercise — fed by ONE set of deterministic on-device targets
(`StrandAnalytics.DailyTargets`, pure + pinned; `Repository.liveTargets` derives, and
`cachedLiveTargets` memoizes for the 1–3 Hz tick closures):

- **Calm HR ceiling** = median of the last 7 nightly resting HRs + 25 bpm, clamped 70–110. Banner
  HR becomes `~72/85` (tilde = live beat, plain = average/frozen); the value tints red above the
  ceiling — the meditate cue (honest during workouts, which legitimately read red).
- **Calorie target** = the charge band (67+ push / 34–66 maintain / ≤33 recover — the coach
  prompt's own autoregulation bands) picking p75 / median / p25 of the last 14 days' active-kcal
  estimates, rounded to 25 kcal. The Cal column shows `now/target`.
- **Sleep need tonight** = the personalized need (population-anchored upper quartile — the SAME
  estimator every debt surface uses) + half the rolling ledger's debt, capped at 90 min,
  deadbanded. The Sleep column shows it as `8h05`.

Charge leaves the banner (its band set the targets; it stays in the expanded island). Effort and
Rest leave the card for the synthesis. ContentState grows four nil-default fields, so an older
build's activity still decodes.

The synthesis default prompt becomes three bold pillar lines (**Rest & sleep** / **Breathing &
heart** / **Activity & exercise**), and the coach context gains a `TODAY'S TARGETS` block stating
the same numbers plus a right-now HR (two-minute mean over persisted samples) vs the ceiling and
the precise "asleep by" time (habitual wake = learned midsleep + half the typical night, #547).
The effort target rides in the synthesis; the card's activity surface is calories. All targets
deterministic — the LLM is forbidden to invent alternatives.

**Verify on phone:** banner shows HR n/ceiling · Cal n/t · Sleep; synthesis regenerates in the
three-line pillar shape citing the same numbers.
