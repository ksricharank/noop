# 11.1.0.16.9 (build 321)

One change: the live heart rate returns to the Lock-Screen Live Activity card. The Dynamic Island is
deliberately untouched.

Build 320's widget instrumentation is still awaiting its first log — see the 16.8 notes for what to
read. That measurement is unaffected by this build.

## HR on the Lock-Screen card

Prompted by turning continuous HR back on and finding the island showing Effort. The instruction was
in two halves, and the second half is as load-bearing as the first: "for the lock screen live
notification, I realized I want HR, plus steps n/t cal n/t, effort n/t", and separately, "for the
dynamic island, we have the right behavior".

So exactly one surface changes. The banner's four columns become **HR · Steps · Cal · Effort**. HR
takes SLEEP's column rather than adding a fifth, because four is what fits at this type size; Sleep
still reads in the expanded island.

**No new plumbing.** `bpm` and the `live` flag have been pushed all along and were simply not
rendered — the controller's own comment said the field "stays populated" for decode continuity. It
already does exactly what was asked: the window average while locked, the live value while unlocked,
and the wearer's `-1` Lock-Screen setting averaging over the sync window itself. This build only
renders it.

`~` marks a live beat, a plain number a settled average, in that direction deliberately: a card
frozen because no push can reach it is left holding the honest plain form, so the tilde can always be
trusted to mean "beating now". A dash when there is no reading at all, matching every other column's
degrade rule.

### History, since this row has now changed hands twice

An HR column led this banner through 10.6.0.14.9 and was removed on 260830 by maintainer instruction
in favour of the three targets. It returns here. The HRV-dip "go breathe" cue does **not** come back
with it — that moved to the stress check-in's strap buzz + screen notification on the same day and
stays there.

### The island was reverted, not trimmed

An earlier draft of this change also rewrote the Dynamic Island (HR-only compact and minimal slots, a
restructured expanded region carrying five target pairs). The maintainer narrowed the scope before it
was committed, and it was reverted wholesale rather than edited down — the island is byte-identical
to 320, and the commit's diff contains no island lines at all.

A test pins the PAIRING rather than just the card: the banner's four columns AND that the island's
compact slot still shows effort. An edit that improved the card while quietly restyling the island
would satisfy half the instruction and break the other half, and that is precisely the kind of drift
a test can catch and a reviewer will not.

## Why HR belongs here and not on the widget

Worth recording, because it answers a question asked directly and because the widget-lag
investigation is running in parallel: "I am assuming the notification widget on the lock screen will
update as frequently as the live notification?"

No — and the asymmetry is large:

| | Live Activity | Lock-Screen widget |
|---|---|---|
| Updated by | the app pushing directly | a WidgetKit timeline reload |
| Unlocked | ~2 s | on request, budget permitting |
| Locked | 60 s, or the wearer's `-1` window | ~15 min timeline policy |
| Reload budget | **not charged** | the ~40–70/day being measured in 16.8 |

A Live Activity is the only lock-screen surface that can carry a genuinely live number, and it costs
nothing against the budget the widgets are competing for. The same number on a widget face would be
up to 15 minutes stale and would spend budget to get there — which is why this change stops at the
Live Activity.
