# 11.8.0.18.20 (build 421)

The digest file, made worth reading.

## What the 260921 07:37 file was

> what gives? that doesn't make sense

A snapshot of the exact instant the 18.16 install launched: an abandoned pass had just evicted
Sep 1–20 and left today unscored, `repo.days` held three August rows, and the launch hook wrote the
digest **before** the foreground pass restored anything — "no data for today", "no sleep last night",
"yesterday not scored". Because a write settles the day's slot, that stood as the day's digest. It was
also self-contradictory: "yesterday not scored" while the grades list below showed Sep 20 = 30, because
the grade was recomputed from the (gutted) daily rows while the list read the stored series.

## Two fixes

**It waits for last night.** `Input.isReady` requires a scored night. A due slot with no night yet is
skipped with `integration: due but last night is not scored yet — waiting for the next sync`; the
post-offload hook retries on every sync. Past a 6-hour grace from the slot's start it writes the
honest thin digest anyway, so a night the strap was not worn does not silence the day.

**It says more, and never contradicts itself:**
- **Sleep debt** under Last night: *Sleep tonight 9h 04m — my 8h 43m need plus 21m toward the carried
  debt*, the carried figure, and the net versus need over the window. The same rule the card, the
  coach and the widget use.
- **Versus my typical night**: total, deep, REM and light against the 30-night typical.
- **Yesterday's grade** falls back to the stored score (with its band) when the breakdown cannot be
  recomputed, so it can never disagree with the list beneath it.
- **What the last weeks say**: the same on-device INSIGHTS block the Trends coach receives —
  week-over-week means, load balance, the gated relationships, consistency, nights meeting the need.
