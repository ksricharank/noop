# 11.8.0.18.2 (build 403)

Finishes the 260919 batch. Two screenshots and a five-point list.

## The widget

WidgetKit already insets widget content, so the face's own 12/10 padding sat **on top of** that and
carried a visibly double gutter on all four sides — most of a 158pt widget spent on margin. Trimmed
to 4/2, the minimum that keeps the progress tracks off the rounded corners, and the reclaimed space
went to the content: mark 22 → 27pt, battery pips and percentage up, tracks 3 → 4pt.

Background is now **pure black** rather than `surfaceBase` (a near-black grey), matching the
Reminders widget so it sits flush on a dark wallpaper instead of reading as a lighter tile floating
on it.

Lock Screen row spacing 2 → 5pt, so Steps/Effort and Cal/Water read as two pairs rather than one
four-line block.

## The Trends "sparse" message was a real bug

Reported as a glitch, and it was one — but not the one it looked like.

The caption was computed from **`recovery` alone** while sitting above six metrics. On an install
whose Charge is sparse but whose HRV, strain and rest are not, the page announced
`3 readings · sparse, widened to 3 months` over charts plotting a full month. The widening itself
was working correctly; the caption was simply speaking for a page it did not describe.

It now describes the page: the widest window any metric had to widen to, with the count from the
**densest** metric, so the line matches the fullest chart under it rather than the emptiest. A
per-metric shortfall is still visible on that metric's own card, which is where it belongs.

## Every tab's summary: open by default, and moveable

- **Recap's was nested inside the breakdown card**, so it could not be moved at all. Lifted into
  its own `DaySection.insight`.
- **Sleep's** is `SleepSection.insight`, defaulting to just before Stages as asked, rather than
  pinned under the hero.
- **Trends had no section system at all** — its nine cards were hard-coded. It gains
  `TrendsSection`, `TrendsLayoutPrefs` and an Arrange sheet, twins of Sleep's and Recap's down to
  the decode-recovery rules (unknown rawValues dropped, missing ones appended, so a layout stored
  by an older or newer build still opens).

  The range bar is deliberately **not** a section: a page whose window selector could be hidden
  would have no way to choose a window.
- **Today's synthesis** was already arrangeable and is never collapsed, so it needed nothing.

## One regression, caught by a test

Lifting the Recap narrative out of `DayQualityCard` broke `CoachMarkdownRenderingTests`, which pins
that every coach-prose surface renders through MarkdownUI rather than a plain `Text` (a plain one
shows the model's `**bold**` as literal asterisks — a bug this codebase has already had once).

The check now points at the shared `TabInsightCard`, which means the three tabs using it inherit
the guarantee rather than each needing its own entry. That is the third time in three builds a
test has caught something a review would not have; the pattern is worth naming.

## What the next log must show

Unchanged, and still the two that matter:

1. **`writeBack=<each>×<runs>`** — the first honest read of the Apple Health write cost. Compare
   the per-run figure to the reads on the same line, never to an earlier log's `writeBack`, which
   was divided by the wrong denominator.
2. **Whether `maxMs` and `longest` have stopped being the same integer.** They shared a key until
   18.0.
3. Whether the Today summary reads as a state rather than a target list — 18.1 fixed that by adding

   whole story.
