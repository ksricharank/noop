# Fork release 10.6.0.15 (build 290)

The v15 refactor (260901): **zero behavior change by construction** — the 16-branch v14 stack was
consolidated into 7 durable branches and the result verified **tree-identical** to
release-10614-14 (the 10.6.0.14.14/276 build on the phone) before anything else moved. Then the
whole set was rebased onto the new upstream tip (`caa9d37d`, which landed overnight: stale-pairing
clear #1790, reconnect-cost work #1779/#1781, standard-HR contact #1769, pre-sleep HR feedback
#1772, sparse-bridge bound #1782). The version counter moves because the FEATURES set changed;
the code's fork content is the same.

## The new shape (the maintainer's spec)

1. **`feature/v15-synthesis`** — the synthesis page and everything LLM: horizons, per-provider
   key slots, observable model fallback + retry, timeout budget, unified Refresh, the editable
   system prompt, the extra sleep detail/trends fed to the model (the toggle).
2. **`feature/v15-widgets`** — lock-screen + iOS widgets and the synthesis numbers: steps n/t,
   cal n/t, sleep target, effort n/t; three-pillar card, Dynamic Island presentation, breathe
   automation, calendar-day rollover, frozen effort target, reload dedup, publish/scan stats.
3. **`feature/v15-battery`** — live-HR battery optimizations: locked-stream duty cycle, the
   night-window (sleep-window) pause, locked re-score deferral + pacing, background light
   re-score, and both instrumentation sets.
4. **`feature/health-read-only-sync`** — Apple Health integration (unchanged, already atomic).
5. **`feature/bond-loop-repark`** — BLE reliability, kept separate as the upstream-worthy #1539 fix.

Plus the two meta branches, unchanged in role: `feature/release-branch-tooling` and
`feature/release-by-default` (now stamping 10.6.0.15 / build 290; upstream staged 289, so the
recurring build-number conflict resolved upward to 290).

The three v15-* branches are a documented linear chain (battery → synthesis → widgets) — down
from the v14 five-deep re-homing tangle. Two previously by-hand release-merge fixes became
permanent commits: the `revalidateHandle()` resolution and `updateFromData`'s epoch bump (the
recurring dynamic-ui-bug-fix × duty-cycle conflict is gone for good). The old branches survive
on origin under their v14 names; tag `pre-v15-refactor` pins the exact installed state.
