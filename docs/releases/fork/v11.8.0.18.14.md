# 11.8.0.18.14 (build 415)

Four asks from the 18.13 install, a bug the maintainer's screenshots exposed, and a crashing test
that had been hiding four fifths of the suite.

## The nap fix was live on a path nothing reads

Two screenshots, minutes apart, same nights:

- Sleep tab's debt card: **−20m**
- Today's "How these were set": **"you're 45 min short lately"**

18.12 threaded nap credits into `liveTargets(forDay:)` and this file reported it fixed. But
**`cachedLiveTargets`** is the path the Today strip, the widgets, the Live Activity and — since
18.13 — the Sleep narrative all call, and it was still passing nothing.

The fix was real, tested, and installed on a code path no surface uses. Both paths now pass
`napSleepMinByDay`.

Worth stating as a rule: threading a parameter through *a* call site is not threading it through
*the* call site. `grep -n 'liveTargets(' Strand/Data/Repository.swift` lists five; only one of them
is what Today reads.

## Sleep: stage bars off, and the ledger in the narrative

The per-stage breakdown bars (Awake / Light / Deep / REM) are **off by default**, with a toggle at
**Settings → Appearance → "Sleep stage bars"**. The hypnogram above already shows the night's
architecture; the bars restate it as numbers, which is useful on request and a wall of bars
otherwise.

The toggle lives in Settings rather than the Arrange sheet because that sheet is a generic reorder
list with nowhere to host a switch — and this belongs beside the Sleep chart style, where the other
sleep display options already are.

**The sleep-debt ledger now reaches the Sleep tab's LLM facts**, built through
`SleepModel.debtLedger` with the same nap credits the card uses, so the two cannot print different
balances. Both of the card's figures are stated, and the per-night need is labelled explicitly as
the **baseline** — with a note telling the model it and tonight's target are different quantities,
because that pair read as one number disagreeing with itself for three builds.

## Trends: the heatmap is gone; the calendar is configurable

The heatmap lasted exactly one build. The calendar was **already** on the page drawing three
hard-coded strips, so rather than have a second grid competing with it, the calendar absorbed the
configurability: any of the nine metrics, reorderable, through the same picker the row card uses.

It defaults to charge / day quality / sleep — the three it already drew — so an existing page looks
unchanged until edited.

Every series normalises to 0–100 before `YearHeatStrip`, which colours cells with
`recoveryColor(score)` internally: a raw HRV or step count would paint every day at the bottom of
the scale. Metrics with no natural 0–100 scale normalise against their **own** observed range so
they spread across the palette; `higherIsBetter` flips resting HR and respiration so a high reading
is not painted as a good day; and the tooltip un-normalises so the reader always sees the real
number.

## A crashing test was hiding the suite

`TargetsExplainerTests` asserted four derivation blocks. After the sleep block was removed it got
three, then indexed `blocks[3]`:

```
Swift/ContiguousArrayBuffer.swift:692: Fatal error: Index out of range
```

That took the whole run down at **523 of 2470 tests**. Every suite it had reached passed, so the
summary line read `0 failures` — a clean-looking result covering four fifths of a suite that never
ran.

**The lesson for the next session: check the test COUNT, not just the failure count.** A sudden drop
from ~2470 to 523 is a crash, not a smaller suite.
