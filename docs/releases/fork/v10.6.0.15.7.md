# Fork release 10.6.0.15.7 (build 297)

Three fixes from the 260903 water-row report, all on `feature/v15-widgets`.

## The +/− lag was a stale memo, not slow code

Reported: the synthesis water +/− "has significant lag … which makes it hard to track".

The water row reads `cachedLiveTargets()`, which is memoized on `refreshSeq` — and a hydration
write deliberately never bumps `refreshSeq` (#989: water is not strap data, and a full data
refresh per logged cup would be absurd). So after a tap the memo returned the SAME cached targets,
and the number only moved when an unrelated strap sync happened to bump that counter. Not slow —
waiting.

- `hydrationSeq` now joins the memo key, and the row reads it so SwiftUI subscribes to water
  writes.
- Both controls move the displayed count IMMEDIATELY, before the store write — which is four
  awaits on the SQLite store (`storeHandle`, the manual total, the upsert, the imported total) and
  can queue behind a strap sync. The authoritative write still runs right after and re-derives the
  figure from the stored entries, so a failed write self-corrects on the next refresh rather than
  leaving an invented number on screen.

## The water target is now frozen, like the other four

Water was the last target whose DENOMINATOR still moved during the day: it priced off
`today?.strain`, so "4 cups left" could grow after a workout — exactly the goalpost-moving the
effort target was frozen to stop on 260831. It now prices off the ANCHOR's effort (the last scored
day), frozen at the morning score.

The formula, unchanged and confirmed as just two terms:
`target = round₅₀(baseline_for_sex + effort/100 × 700 ml)` — 3700 ml male baseline, up to +700 ml,
nothing else (no charge, no sleep, no temperature). At effort 0 that is 16 cups; at 100, 19 cups.

**Stated trade:** an unplanned hard session raises TOMORROW's water ask, not today's. The
derivation block and the coach context both say "yesterday's effort … frozen at this morning's
score" rather than implying it is live.

For the record, the calorie target was never live — `dayKcalTarget` prices the anchor's PRESCRIBED
session through the Keytel model (not a linear fraction of accumulated effort), so all five
targets now hold still together.

## A seam between the derivations and the coach's prose

The coach's Markdown ran straight on from the "How these were set" derivations with nothing marking
the boundary — two different kinds of writing (deterministic arithmetic vs the model's prose)
reading as one block. The liquid Today view gains a rule plus a tappable "Written by your Coach"
header (with the model name) that collapses the prose; expanded by default, session-local. The
classic Today view already renders the coach in its own card, so it gains only the collapse.
