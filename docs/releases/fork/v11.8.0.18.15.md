# 11.8.0.18.15 (build 416)

One widget where there were two, and a Settings toggle that stopped making sense the moment it
merged.

## Stage breakdown absorbs "vs typical"

> for stage breakdown in sleep, right in that widget can you add the comparison to stages vs
> typical (which is now a separate widget) - will allow me to use one widget for two things

Each breakdown row — REM, Deep, Light — now carries its own `+/− vs typ` delta beside the duration,
which is the entire content of the old `StagesVsTypicalCard`. Green above the personal mean, amber
below.

**Inverted for Awake**: more time awake is the worse night, so shading it like the others would
praise the wrong direction.

Awake renders with **no delta at all**. The model has no `typicalAwakeMin` — and the old card did
not show one either — so the absent comparison is stated by absence rather than as a fabricated
zero.

## The toggle went with it, and the reasoning inverted

18.14 hid these bars behind **Settings → Appearance → "Sleep stage bars"**, on the argument that
they restated the hypnogram as numbers.

That argument dies with this change. The bars now carry the **only** copy of the vs-typical
comparison, so putting them behind a Settings switch would bury a reading nobody would find. They
are always shown again; the preference key and its Appearance row are gone.

Worth noting as a pattern: a toggle added to hide redundancy becomes wrong the moment the thing
stops being redundant. One build's correct default is the next build's buried feature.

## The standalone card is hidden, not deleted

`stagesVsTypical` is **default-hidden**. Its content is in the stage rows now, and leaving it shown
would put the same comparison on the page twice.

Hidden rather than removed because deleting the rawValue would make every stored layout containing
it decode short — and the recovery rule *appends* missing cards, it cannot restore an order it never
saw. Anyone who prefers the separate card can un-hide it in Arrange.

`SleepCustomizationSheet` reads the same `effectiveHidden` the page does. Seeding it from the raw
stored set would list the card as "Shown" while the page hid it — the exact page/sheet disagreement
the Trends sheet hit earlier the same day, avoided here by reusing the rule rather than
re-deriving it.

## Verification

Both app targets compile. The full 2470 macOS tests run, with only the two pre-existing
`SkinTempAbsoluteDisplay` / `SleepCarriedStamp` failures already confirmed on a clean v11.8.0
worktree.
