One consolidated build for the three items left open after `.13` (whose locked-span island fix the

**1. The Live Activity's "Rest" is now the Rest SCORE** (`feature/locked-stream-duty-cycle`). The
banner stat carried resting HR while the app's Today "Rest" tile shows the 0–100 sleep-performance
composite — one label, two metrics, so they could never agree ("the rest scores don't match"). All
four call sites now read the new `Repository.restScore(for:)`: the same layering Today's tile
resolves — an imported export's verbatim `sleep_performance` wins (`importedSleep`), the on-device
Rest composite fills computed days, byte-identical to the engine-persisted series (IntelligenceEngine
writes exactly `AnalyticsEngine.Rest.composite(daily:)`). Synchronous over cached state, so the
live-tick closures afford it. Charge/Effort/Rest all read the same widget-anchor day, so the card
stays internally consistent (today once scored, else the freshest scored prior day — #911).

**2. Banner numbers one step bigger** (same branch): values `.headline` → `.title3` semibold,
labels stay `caption2` — the four numbers are the banner's whole payload and read from a nightstand
distance.

**3. Wake counters survive relaunches** (`feature/battery-instrumentation`). The `.12` log proved
the per-process counters useless for a day verdict: the overnight process relaunched at 07:31, its
totals died with it, and the header extrapolated a 30 s launch offload burst into "224148/h over
0.0h". Counts now ALSO merge into a per-local-day UserDefaults bucket (today + yesterday only),
flushed on the offload-completion path (one small defaults write per ~10–15-min sync) and at
export. The header gains `BLE wakes today:` / `BLE wakes yesterday:` total lines, and a session
window under ten minutes reports its honest span with no hourly rate. Pure merge/prune +
formatters pinned in `BatteryDiagTests` (9 tests).

Verified: both apps compiled per branch; `BatteryDiagTests`, `LockedStreamPolicyTests`,
`DeviceLockStateTests` pass.
