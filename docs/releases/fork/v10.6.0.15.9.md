# Fork release 10.6.0.15.9 (build 299)

Two 260903 reports, both on `feature/v15-widgets`.

## The coach was parroting the prompt's examples

Reported: every pace nudge arrived titled "Big push left, block an hour" — "is the LLM not
working?"

The LLM was working. That line was the **fifth worked example in the title prompt**, returned
verbatim. The few-shot examples sat too close to the task and nothing forbade reusing them, so the
model copied one — and the result was indistinguishable from a genuine generation OR from the
plain-title fallback.

- The examples are reframed as shape-and-length illustrations, with an explicit instruction to
  refer to the user's own numbers and never reuse the wording.
- A returned example is **rejected in code** (case- and trailing-punctuation-insensitive), so the
  plain title is used rather than a line that says nothing about the day.
- **The outcome is no longer invisible.** Every attempt records why it succeeded or failed — no
  provider / data consent off / no API key / request failed (with the provider's reason) / reply
  rejected (with the reply's first 60 characters) / written by `<model>` — and both call sites log
  it to the strap log. This is precisely the evidence that was missing: a generic-looking title had
  no way to be told apart from a working one.

## Every nudge figure now carries its unit

The trailing number on each row was ambiguous across the three rows. Now: `22 min walk`,
`45 min workout`.

Cal additionally quotes the **prescribed workout** while one is still open, because the walking
equivalent of a calorie gap is absurd — a ~330 kcal shortfall is ~20 minutes of exercise or ~80
minutes of walking, and quoting the walk reads as a punishment for a gap the day's plan already
answers. With the workout done, it falls back to the walk equivalent (~4 kcal/min).

So a fully-behind afternoon now reads:

```
Behind pace
Steps 1500/3750/10000  22 min walk
Cal 980/1472/2525  45 min workout
Effort 0/22/59  45 min workout
```
