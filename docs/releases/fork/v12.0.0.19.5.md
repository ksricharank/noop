## Integration digest: the wearer's own clock times + Sync now

The 260922 cadence (N/day evenly spaced from the sleep window's end) fired its
first write AT the window boundary — mid-sleep on any longer night, and the
readiness guard can't help because a partial night IS a scored night. The log
shows exactly that: `integration: written (2/day, slots from 06:00)` carrying a
4-hour night to the digest's reader. Replaced with up to SIX explicit clock
times (empty slot = skipped; none set = manual only), same once-per-slot and
catch-up-at-next-opportunity rules, migration derives the equivalent times from
the retired count once. "Sync now" on the schedule card writes on demand
(replacing the actions card's "Generate now") and still chains the Shortcut.
Log line is now `integration: written (slots 06:30,19:00)`.

## Summaries follow the screen (all four tabs)

Report: sleep moved 4 h → 8 h on screen; every LLM summary kept saying 4 h; the
first refresh tap did nothing; only the second caught up. Three faults fixed:

- `refreshSynthesis` stamped `synthesisDataSeq` AFTER the provider call, so rows
  landing mid-generation donated their new seq to text written from the old
  rows — `refreshSynthesisIfDataChanged` then judged the stale text current.
  Now captured before the context is built and stamped verbatim.
- A forced refresh during an in-flight generation was silently dropped by the
  `!synthesisInFlight` guard (where the tap went — the open-triggered
  generation queues behind the Health sync's store reads). Queued now; the
  running generation re-runs once when it finishes, and data moving under a
  generation triggers the same bounded re-run with no tap.
- `TabInsightCard` (Sleep / Recap / Insights) had no data stamp at all: its
  cache keys on the SUBJECT, which doesn't change when fuller rows land under
  it. It now records the `refreshSeq` its text came from, regenerates when
  superseded while expanded, and re-runs once on mid-generation lands.

Quiet cases spend nothing: collapsed cards, idle tabs, and byte-identical
refreshes (the repository diff guard) never fire.
