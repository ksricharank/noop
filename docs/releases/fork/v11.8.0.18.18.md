The guards held; there is no second hole. Battery populated on every publish. And the structural

## The baseline fix

On a strap-only install the imported history is empty, so the HRV/RHR/resp baselines were folded
**entirely from the nights the current pass scanned**. A completed pass scans 21 and scores; a partial
pass — light, or a full pass the abort gate stopped at night 1 — scanned one or two and *could not
score anything*. That is the whole reason today's Charge waited for a foreground open.

A partial pass now folds the other nights of the standard window from its **own stored computed rows**
(what a completed pass wrote), and only for days it did not scan, so nothing it is about to rewrite
feeds its own baseline. A completed pass scans every day: the set is empty and its output is
byte-identical. Android has no partial passes, so there is no twin to keep in step.

With a real baseline behind it, the write rule becomes: **a partial pass may fill a blank Charge,
never overwrite one.** `lightPassMerged` still takes every scored-night field from the stored row —
the light pass is for numerators — but a day with no stored Charge yet (a new day, before the
morning open) gets the fresh value. Expected tomorrow: the post-offload light pass after the night
lands writes today's Charge in the background; the widget shows it before the app is opened; the
first paint on open is today's, not yesterday's.

The `chargeWrite` ledger now reports the value actually persisted (`wrote=62 stored=none` on the
morning's first light pass is the line to look for) and `hrvNValid` should read ~21 on partial passes.

## The lag in 18.16/18.17 was mine

The `chargeShown` ledger added `@EnvironmentObject var live: LiveState` to the liquid Today. That
subscribes the whole Today body to the 1 Hz heart-rate stream — the regression SleepView's header
warns about, in the default screen. Removed; screen-side lines go through a static sink
(`ScreenLedger`), the same shape `DisplayPerformanceMonitor` uses.

## Screen performance

- **Liquid Today re-mount cache.** Upstream's liquid rewrite never carried over the classic Today's
  `#849/#932` cache, so every return to the tab re-ran ~20 store reads — a 200k-row raw-HR query and a
  full-history StressModel among them — for byte-identical data. A same-key re-mount now restores in
  memory. The key is the exact `.task(id:)` string, so any data change misses on purpose.
- **Sleep tab re-mount cache** for the four heavy loads (every session, per-session motion, habitual
  midsleep, the Rest series), keyed on `refreshSeq`.
- **Trends `multiMetricSeries`** — seven full passes over `repo.days` ran on *every body evaluation*
  (mine, from 18.14), and the heart-rate sink re-evaluates bodies once a second while the strap is
  connected. Built once per data change now.
- **Asleep-duration chart non-interactive** (maintainer request) — same zero-distance drag gesture the
  Recap chart was cured of on 260920; a swipe over the bars scrolled the chart instead of the page.
- **`screenLoad screen=… ms=… restored=…`** — one line per tab load, so the switch cost is measured
  from here on instead of felt.

## One sleep need

Three figures for one body: the ledger's per-night need (**8h27** — upper quartile over all history),
tonight's target (**8h05** — a population floor with charge / rest / readiness notches plus a debt
share), and Day quality's "needed" (**7.6h** — yesterday's copy of that target). None derivable from
the others on screen.

Now `SleepModel.personalNeedMin` is the only estimator: `personalizedNeedHours` over the trailing 21
nights with sleep — the same estimator and window the engine's Rest score uses. The ledger, the Sleep
tab's need, Day quality's "needed", the coach, and tonight's target all read it. Tonight's target is
**need + a quarter of any carried debt beyond the deadband, capped at 45 min** — nothing else. The
charge / rest / readiness notches are retired; they were the unexplained gap. Day quality's config
fingerprint carries `/need21`, so history re-scores under the one need.

## The ledger card reads as it computes

The bars are raw per-night deltas; the headline is the *carried* debt (55% carries to the next night,
settled under 10 min, a surplus never banks). Eight red bars under "On target" is that model, not a
bug — but it read as one. The footer now shows **Carried debt** and **Net vs need** (the plain sum of
the bars) side by side, and the plain-English read says both when they disagree.

## The coach

- **Trends** was asked to find trends in a table of rows and produced generalities. It now receives an
  **INSIGHTS** block computed on-device — week-over-week means per metric, load balance, the lagged
  relationships that clear a statistical gate (n ≥ 10, |r| ≥ 0.3, p < 0.1), day-quality consistency
  and streaks, nights meeting the need — ranked, and a prompt whose job is the "so what".
- **Sleep** gets the stage split against the 30-night typical (the same deltas the stage rows show) and
  the one need.
- **Recap** gets the day in context: this score against the mean of the previous 30 and the positive
  streak into it.

## The digest

- **No clock time.** One setting: **Updates per day** (1–12), evenly spaced from the end of the sleep
  window — the app's own "morning" (default 07:00). 1 = once, the first time the app is running after
  waking. The old hour + interval pair migrates once (24 h → 1, 6 h → 4).
- **Runs in the background.** It rides the post-offload hook with the widget publish and the
  automations, so the file lands on the first strap sync after the anchor with the phone in your
  pocket. Launch and scene-phase `.active` remain as catch-ups. Idempotent per slot.
- `hasFolder` resolves the bookmark instead of trusting that bytes exist; an `integration:` log line
  says written / failed / due-but-no-folder — never on the common "not due".

## The widget after minimising

The exit publish — the one whose job is to make the widget match what was just on screen — ran after
`applicationState` already read `.background`, so it went through the background spacing gate and was
**coalesced** whenever a strap sync had published within the previous 120 s. It is user-initiated and
one per exit; it is now budget-exempt (`exempt=true` in `chargePublish`).
