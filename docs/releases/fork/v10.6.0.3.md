## Reinstalling this build

**Clear the provisioning profiles first, then build.**

```bash
rm -f ~/Library/Developer/Xcode/UserData/Provisioning\ Profiles/*.mobileprovision
```

A free personal team issues 7-day profiles, and Xcode reuses an existing valid one rather than
minting a new one — so rebuilding does *not* reliably reset the clock, and the app can die mid-week
after what looked like a fresh build. This build's profile expires **1 September 2026**; the app
stops launching then regardless of anything in the code.

If the app has already died, this is still the fix — it just costs a reinstall.

## Coach and Today synthesis

**A powerful model no longer produces nothing.** The root cause was never the retry: the coach ran
on `URLSession.shared`, whose `timeoutIntervalForRequest` defaults to 60 s (Android's OkHttp read
timeout was the same 60 s). These requests are non-streaming and capped at `max_tokens` 4096, so
nothing arrives until the whole reply is written, and a reasoning-class model composing a long answer
routinely passes 60 s. The request was killed mid-generation every time and surfaced as a failure
rather than a slow success — picking a more capable model made it strictly *more* likely to fail.

Both platforms now use a 180 s budget. Both timeouts are between-bytes stall budgets rather than
deadlines on the answer's length, so this bounds a wedged request without capping a long one.

**The retry no longer wastes a second full timeout.** On the cheapest model — or Custom, which has no
cheaper id — it re-sent the identical request, so the user waited out another full budget to see the
same error. It is now skipped unless there is a genuinely different, faster model to switch to: the
first attempt already proved the deadline is the binding constraint, not luck. The timeout message no
longer claims a retry that may never have run.

**The setup card is no longer a dead end.** Its only exit was "Save key", disabled while the key
field is empty — and that field is transient, cleared after every save and never prefilled from the
Keychain, since a stored secret cannot be read back into a field. So a user who had already saved a
key returned to a card they could not leave.

## Build and release tooling

**The provisioning reset is now step 4 of the procedure,** not a trap buried at the bottom of
[`FORK-RELEASE.md`](../../FORK-RELEASE.md). It was documented as a remedy to reach for once the app
had already died, by which point the build is off the phone and has to be redone. The release script
prints it as the first "next step", and these notes restate it above, because the notes are what gets
re-read when reinstalling a build weeks later.

**Step 5 now says how to check the signing identity resolved** before pressing ▶. A worktree missing
its gitignored `Config/BundleIdSecrets.xcconfig` builds as `com.noopapp` with no team and fails only
at the signing step — see below.

## Signing

**The Team ID was wrong or missing in three of five checkouts.** All are now `XTV757K5W7`, read off
the certificate's `OU` rather than guessed:

```
CN=Apple Development: sricharank@gmail.com (2AGL4ZKM66), OU=XTV757K5W7
```

`2AGL4ZKM66` is the Apple ID identifier and `XTV757K5W7` is the Team ID. One checkout held the `CN`
value, which makes every target fail to find a provisioning profile; another had no
`DEVELOPMENT_TEAM` at all; a third had no `BundleIdSecrets.xcconfig` at all and so built as
`com.noopapp`. Because the file is gitignored, this drift is invisible to git and has to be checked
per worktree — with `-showBuildSettings`, never by reading the file you assume is in use.
