## Integration page: the saved write times show when it is reopened

The maintainer's report: "I can't change the default times of 7:45 am and 9:15 pm — when I edit those
values and go back and come back to the page it still shows the old values."

The edits WERE saved. Settings builds the Integration page eagerly (`NavigationLink { IntegrationView() }`),
so every `@State` on it was seeded from the store when Settings last rendered, not when the page
was opened. Re-opening therefore showed the times from before the edit. Worse, editing again from
that stale page wrote the stale times back over the others. `IntegrationView` now re-reads every
stored setting on appear: enabled, filename, times, Shortcut name and delay, coach narratives,
folder, and last write.

## Also answered (no code): why the 7:45 Muse file held the previous night

The 07:45 slot is written at the first strap sync AFTER 07:45, and only once last night is scored.
The logs show writes at 07:45:15 and 07:56. A Shortcuts time automation at 07:45 therefore ships the
file before it is rewritten, and gets the previous evening's 21:15 digest. The fix is to move the
automation about 30 minutes after the slot, or the slot about 30 minutes before it.

## What to check
