# 11.1.0.16.10 (build 322)

The Dynamic Island change that 16.9 should have carried: heart rate when collapsed, the day's pairs
when expanded.

Build 321's Lock-Screen card is confirmed good ("the live notification looks great") and is untouched
here.

## What 321 got wrong, and why

The original instruction was "I want the island to show the live hr only, and same thing for the live
notification - just the HR (the N min average on lock, live on unlock, the 15 min average when -1)".

When the maintainer then said "for the dynamic island, we have the right behavior", I read it as
"leave the island alone" and reverted the island work wholesale. They were confirming the CADENCE —
window average while locked, live while unlocked, the `-1` window — which the controller already
did correctly. That message was narrowing the LOCK-SCREEN CARD (from HR-only to HR plus three
pairs); it never withdrew the island request.

So 321 shipped the island still showing Effort. Worse, I then wrote a test asserting that as
CORRECT, which would have kept it wrong through any future change. Reported as "the dynamic HR is
messed up - you didn't implement any of the changes I asked for".

Recorded at length because the failure was not a coding mistake — it was reading a narrowing
correction as a full retraction, then encoding that reading into a test. The lesson for the next
ambiguity: when a correction arrives mid-change, restate which half it applies to before acting on
it.

## The island now

**Collapsed** (compact trailing + minimal): the live heart rate, alone. The compact slot marks a live
beat with `~`; the minimal slot shows the bare number, because at a ~24 pt circle the tilde costs a
digit of width for a distinction the slot has no room to make. No reading yet falls back to the heart
glyph rather than a dash — a lone en-dash reads as a broken widget.

**Expanded**: HR leading, Charge trailing (its band is what SET today's targets, so it explains the
row beneath it), and five pairs across the bottom — Effort, Steps, Cal, Water, Sleep. That is the
list the maintainer asked for: "hr, sleep target, steps n/t, cal n/t, effort n/t, water n/t".

Effort did not leave the island; it moved from the collapsed slot to the expanded region. Collapsing
to a pure heart-rate readout is only defensible because expanding still answers everything else.

Steps rejoins the island, having been banner-only since 260830 ("I don't need steps in the island") —
the new instruction names it explicitly and supersedes that. Water is new to the Live Activity
entirely: `ContentState` gains `waterHalfCups` / `waterTargetCups` under the same nil-default
decode-compatibility rule every other field there follows, and the controller populates them at all
three state-construction sites.

The static "HR" title label left the bottom region to make room. Not lost data — it was a fixed
string naming the session, on a region that now leads with a heart icon beside a live heart rate.

## No new plumbing, again

Worth restating because it is what made both halves of this cheap: `bpm` and the `live` flag have
been pushed all along and were simply not rendered. The controller already does exactly what was
asked — window average while locked, live while unlocked, the `-1` sentinel averaging over the sync
window — and its own comment said the field "stays populated" for decode continuity. Only water
needed new fields.
