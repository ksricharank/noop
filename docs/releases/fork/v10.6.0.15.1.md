# Fork release 10.6.0.15.1 (build 291)

Two maintainer instructions on the morning of 260901, same day as 10.6.0.15 shipped.

## Light-pass blackout is midnight → window end, not the whole sleep window

10.6.0.15's Fix 1 skipped the light pass for the entire sleep window (22:00–06:15). The
maintainer's spec: keep updating through the evening leg — the user is awake at 23:00 and the
numerators still move — and stop only at local midnight, where the day rolls anyway and the
counters restart from zero. `lightPassWanted` now takes `minuteOfDay` + `windowEndMinute` and
skips exactly the after-midnight leg (00:00 → 06:15 for the default window; a non-wrapped window
like 01:00–06:00 is entirely after midnight and skips whole). ~8 evening passes/night return;
the ~38 truly-asleep ones stay skipped. (`feature/v15-battery`)

## A zero effort target keeps the pair form: "0/0", then "x/0"

10.6.0.14.14 made a REST day's effort target nil, degrading the displays to the bare numerator —
which hid whether any strain had accrued. Maintainer instruction: the target is ZERO, never nil,
so a rest day reads "0/0" and becomes "x/0" as ambient strain lands. One change in
`Repository.liveTargets` covers every surface — the strip, both widget faces, the Live Activity
card, and the banner all format pairs whenever the target is non-nil, and none of them clamp the
numerator, so n > t stays visible as-is on all three pairs (verified per surface; pinned by the
rewritten rest-day invariant + a zero-target/no-clamp WidgetSnapshot test). The coach's rest-day
line now reads "hold near 0.0" — the honest prescription. (`feature/v15-widgets`)

## What the next log must show

  the first post-window sync.
- On the next rest day: widgets/strip show "0/0" effort at dawn, "x/0" after any walk.
- Everything else per the 10.6.0.15 checklist (light done-times a few seconds, lower CPU lines,
  dedup a minority, reloads < 50).
