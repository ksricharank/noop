## Today Refresh: sync first, then score once

Before: Refresh asked for a sync and started a forced full pass in the same instant. The pass
scored the data as it stood just BEFORE the sync. When the sync landed, its quick pass found that
pass still running and skipped, so the fresh steps and calories waited for the next sync (~10 min).
Under 19.17 nothing re-ran them, because an unchanged night asks for no full pass.

Now (`BLEManager.syncNowAndWait`, both Today screens): sync, or join a sync already running, and
wait until it completes: `lastSyncedAt` advances and the link stays idle for 2 s, since a productive
offload auto-continues. Then ONE forced full pass on the fresh data, then the coach read. It returns
at once and scores what is on the device when no sync starts within 3 s (no strap or not bonded), and
gives up waiting after 90 s. One line either way: `Refresh: sync finished — scoring once on the
fresh data` / `Refresh: no sync completed …`.

Pull-to-refresh is unchanged (a sync only, routine path).
