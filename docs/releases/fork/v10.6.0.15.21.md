# Fork release 10.6.0.15.21 (build 311)

Supersedes 15.20, which was cut and never installed. Two buzz fixes on `feature/v15-widgets`; the
FEATURES set is unchanged, so the fork counter stays at 15.

## Why the nudges were silent — two independent causes

Reported from the device: "my whoop is still not buzzing for water (and I think steps and cal)".
The steps/cal one is the **pace check** ("Behind pace", with a row per lagging target), not the
Move reminder — a distinction that matters, because the two have different causes and only one is
in this fork's code.

**1. The master toggle defaulted OFF.** The wiring was correct end to end; the buzz added on request
simply arrived silent and read as broken. A cue nobody asked for should default off; this one was
asked for. Every cue now defaults ON, and the user switches off what they do not want.

Safe to default on because it is self-limiting rather than merely quiet: each underlying nudge keeps
its own enable toggle (so this can never buzz for a nudge that is itself off), and the buzz still
requires an encrypted, bonded link, so a charging or out-of-range strap gets no cue.

This also exposed a latent mismatch: `AutomationsView`'s `@AppStorage` default was `false` against a
logic default of `true`, which would have shown the switch OFF while the buzz was firing. Both are
now stated together with a note that they must agree.

**2. The buzz went out on the unacknowledged path.** `buzzForNudgeIfEnabled` used the bare
`buzz(loops:)` write. `BLEManager.buzzStrapOnce` already documents why that is not enough: a plain
RUN_HAPTICS_PATTERN "can be silently ignored (WHOOP 4.0 via the Siri shortcut) or dropped unacked on
a busy link" — and a nudge fires on the **post-offload** path, which is exactly a busy link. On a
5/MG it also omitted the `runAlarm rev2` follow-up entirely.

Nudge buzzes now take the same hardware-confirmed sequence as the Live "Buzz strap" button and the
Buzz Strap App Intent. Being felt is the whole point; a cue written but not felt is
indistinguishable from one that never fired.

The two breathe sites are deliberately unchanged: they pass a VARIABLE loop count encoding dip
severity, which the fixed 3-loop one-shot would discard, and that cue has buzzed successfully since
it shipped.

## What was NOT changed

**The Inactivity ("move") reminder** stays off by default. It is a separate upstream feature with
its own switch, quiet hours and threshold. It is NOT the source of a steps/cal nudge — NOOP has no
steps-goal notification on either platform; the pace check above is what carries those rows.
