# 11.8.0.18.1 (build 402)

Corrections to 18.0's feature batch, all from one screenshot and a five-point list.

## The widget was mostly empty

Two `Spacer`s pinched the four rows into a band in the middle of the face while the type stayed
small, so a 158pt widget spent most of itself on padding. The rows now divide the available height
between them, which is also what lets the type grow — labels 10 → 13pt, values 15 → 19pt.

Checked by rendering at real point sizes with the widest realistic pairs (`18.4k/8.9k`) on the
narrowest face. Nothing truncates.

On the Lock Screen, row spacing went 2 → 5pt: Steps/Effort and Cal/Water sat close enough to read
as one four-line block rather than as two pairs.

## Today was reciting the targets

Reported as "a plain recap of the targets I need to hit — not really useful", and correctly so.

**The cause was upstream of the prompt.** A right-now HR block was retired in 260830, so the
context held day-lines and today's TARGETS and nothing at all about the hours just past. Asked to
describe current state from that, a model can only restate the targets — which is the one thing
already legible from the numbers on screen. No amount of prompt editing fixes a missing input.

So the context gains `recentStateBlock`: hourly mean HR and range over the last six hours, the
wearer's resting HR as the reference that makes "elevated" mean anything at all, and how long they
have been sedentary. Derived, never raw samples — the same text-only channel as the rest of the
context.

The sedentary threshold is relative to the **window's own floor**, not a fixed bpm: a fixed
threshold calls a resting 70 bpm "active" for one person and never fires for another. A window that
never rises reports the whole window rather than nil, because "you have not moved in six hours" is
the most actionable thing the block can say and returning nil would suppress exactly that.

The prompt now leads with those hours and explicitly forbids narrating target progress. A target
may be mentioned only when the present state changes what to do about it.

## The four summaries, tidied

- **Recap opens by default, in bullets.** It was collapsed, and its prompt explicitly forbade
  markdown — so it was the odd one out among four siblings, a paragraph where the others scanned.
  Opening by default means *generating* by default, a provider call per visit, which is the cost of
  making it the thing the tab leads with.
- **Sleep moved to the top**, from the foot of the arrangeable sections where it sat several
  screens down.
- **Trends and Sleep gained "Ask the Coach"**, matching Today and Recap.
- Trends re-asks when the window changes — an answer about 90 days must never sit under a chart
  showing one week.

## One near-miss worth recording

The Today rewrite dropped the total-calories guard — the line that stops the model reading a normal
early-day calorie number as a shortfall. It survived only because a test pinned it. That is the
second time in two builds a prompt edit quietly removed a guard that a test caught; the lesson is
that prompt text deserves assertions exactly like code does.

## What the next log must show

Unchanged from 18.0, and still the two that matter most:

1. **`writeBack=<each>×<runs>`** — the first honest read of the Apple Health write cost. Compare
   the per-run figure against the reads on the same line, never against an earlier log's
   `writeBack`, which was divided by the wrong denominator.
2. **Whether `maxMs` and `longest` have stopped being the same integer.** They shared a key until
   18.0; if they still match exactly, something else is wrong.
3. Whether the Today summary now describes a state rather than a target list — the fix is a context
   change, so this is the build that says whether the missing input was really the whole problem.
