## The 261009-0745 log (first night on 19.8/444): battery

Working as intended:
- **Concurrent store reads (19.6) paid off.** Health sync avgSyncMs **12,673** (139,634 on 10-06);
  retro stress-scan maxWait **592 ms** (814,943 on 10-06). Normal-pass read cost unchanged (light
  passes 11–28 s of reads on 442/444, against 22–35 s on 441) — no reader-pool regression.
- **Long light-pass totals are suspension, not work.** Passes of 270–600 s show 10–50 s of reads
  plus `paced=`; the rest is the app suspended in the background with the monotonic timer running.
  The occasional 300 s `maxRead` is a read in flight across a suspension. No CPU is spent there.
- MetricKit 10-07 cpu=2,954 s (10-05: 3,058; 10-04: 5,488). BLE wakes ~4.3k/h, the strap's normal
  1 Hz shape. Widgets: 14 of 200 budget, dedup 47/65.

One fault — **the Apple Health write-back leak.** `writeBack=40s×107` in a single 9.3 h process.
`sync()` writes back at most once per sync (14), and the 30-min floor admits about 20 routine runs, so
at least 73 came from `finishHealthPass`'s coalesced re-run, which ran unconditionally. It is armed by
any sync or write-back request landing while a pass holds the bridge — most passes, since observer
wakes burst (711 wakes, 383 empty: NOOP's own writes waking its observers). Each run rewrites a 14-day
window that Health re-ingests — the Apple Health battery share the maintainer still saw.

Fix: the re-run passes `HealthWritebackThrottle` like the two routine call sites. Lossless (the next
admitted run writes the same days, fresher); counted in `skipped=`. Foreground `sync()` unchanged.

## Coach: typing re-renders the input bar, not the conversation

Report: typing in the coach is "very laggy… ok sometimes and not sometimes". The draft was `@State` on
the whole Coach screen, so each keystroke re-parsed the Markdown of every visible message, re-estimated
tokens over the history and recomputed the chips — scaling with conversation length (the "sometimes"),
plus a full re-render whenever a background refresh landed mid-word. The draft is now a reference
object CoachView holds without observing; the field, Send, mic and token estimate live in a
`CoachComposerBar` leaf. No behaviour change. Not measured on device — the next session's typing is
the verification.
