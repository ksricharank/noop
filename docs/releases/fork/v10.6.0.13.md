## .13 — Live Activity: survive locked-span link drops; reopen the restart path

**Symptom (260828-0731, confirmed on device):** lock the phone, wait a few minutes, unlock — the
Dynamic Island is gone and stays gone; only bouncing the Live Activity toggle revives it. Same
mechanism left the island dead every morning (it "turns off during the night" via the sleep-window
pause and never returned on its own — a regression the fully-live builds masked).

**The chain (three defects):**

1. **A locked-span link drop ended the activity.** The duty cycle silences the link by design
   (`TOGGLE 0`, 0x2A37 unsubscribed); the idle link can time out (log: locked 07:17:33,
   "connection timed out" 07:20:55 — the day's ONLY drops were in silenced spans). The `$connected`
   observer then ended the activity — correct while live (#911: never show a frozen number as
   live), wrong while the duty cycle owns the presentation. And the end was one-way: live ticks are
   gated off while locked, and iOS forbids starting a Live Activity from the background.
2. **The corpse then blocked every restart.** `updateFromData` re-adopted
   `Activity.activities.first` without filtering for liveness — `Activity.activities` keeps
   `.ended`/`.dismissed` handles around for a while, so the next sync repaint adopted the ended
   activity's corpse. Every subsequent push vanished into it, and the non-nil handle made the
   restart branch unreachable — even unlocking and opening the app did nothing. (The live path had
   the `.active` filter from the #341 fix; the data path never got it.)
3. **Failures were silent.** `Activity.request` from the background throws unconditionally — and
   after any legitimate end, live ticks re-requested (and re-threw) at ~1 Hz for as long as the app
   stayed backgrounded. The `catch` swallowed everything, so none of this was answerable from a
   strap log.

**The fix:**

- **Hold, don't end, on a locked duty-cycle drop** — new pinned pure rule
  `LockedStreamPolicy.holdOnDisconnect(dutyCycle:locked:)` (true exactly in that one quadrant).
  The frozen window average never claimed liveness, and its staleDate greys it if no successor
  arrives; the standing reconnect's next sync repaints it. Unlocked (or duty cycle off), a drop
  still ends the activity immediately.
- **`revalidateHandle()` on both push paths:** drop a held handle whose activity died elsewhere
  (sleep-window pause, disconnect end, the system's own 8 h lifetime cap) and adopt only live
  (`.active`/`.stale` — a push revives stale) activities. The restart path is now always reachable.
- **Starts only while foreground-active**, plus a scenePhase kick that pushes current values the
  moment the app opens — the island restarts on first app-open with no toggling (iOS's
  no-background-starts rule makes first-open the earliest possible moment after a night end).
- **Rare-event log lines** (always-on, silent when nothing happens): a dropped dead handle, a
  failed start, and "link dropped while locked — holding the Lock-Screen average".

Verified: both apps compiled; `LockedStreamPolicyTests` (9, incl. the new 4-quadrant hold pin) and
`DeviceLockStateTests` pass. On-device check: lock → wait 5+ min → unlock → island resumes; morning
after the sleep window, island returns on first app-open without touching the toggle.

## .11/.12 — banner redesign (shipped 27 Aug, notes folded here)

The Lock-Screen banner is four EQUAL stat columns — **HR · Charge · Effort · Rest** (Rest = the day
anchor's resting HR) — one shared type size, replacing the caption-title + oversized hero bpm that
read as "live beat" even when showing a locked window average. The activity title is now "HR" (was
"Live HR" — dishonest under the duty cycle). `ContentState` gained an optional `rest` (nil default,
so activities from older builds still decode). `.12` dropped the `%` from Charge — no other column
carries a unit. Dynamic Island expanded view carries the same Charge/Effort/Rest columns.
