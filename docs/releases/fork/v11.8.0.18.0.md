# 11.8.0.18.0 (build 401)

The v18 uplift — upstream v11.6.0 → v11.8.0, 160 commits across 454 files — plus the 260919
feature batch. Unlike 17.0 this is deliberately **not** a pure uplift: the uplift and the features
ship together because the strap log that prompted the features arrived in the same session.

## The uplift

Seven feature branches rebased onto the v11.8.0 tag. Upstream built in fork territory again, and
the important outcome is what was **retired** rather than merged:

- **"Move all coach configuration into Settings" is gone.** Upstream's #2243 built
  `CoachSettingsView`, which is a strict superset of the fork's `ConfigureCoachSection` — same
  consent, on-device-signals and derived-trends cards, plus five more. Keeping both would have
  shipped two coach settings screens. The fork's four unique surfaces (the Today-synthesis
  instruction, the notification-title instruction, `derivedTrendsBar`, the morning brief) are
  grafted onto upstream's screen.
- **The `isDeviceLocked` re-score rule is gone.** The fork had already superseded it with the
  sleep-window rule, and it was built on the measured-duration deferral that upstream deleted in
  #2296.

Two fork features were re-verified as **still needed**: the per-provider API-key slots (upstream
still keeps one shared `account = "api-key"`) and the sleep-window deferral. On the latter,
upstream's #2296 replaced duration-based deferral with rest-pacing — complementary, not
competing, so **both** now run: rest for the night just scored, then decide whether to continue.

Two real defects surfaced while unifying the double-tap dedup on upstream's implementation, both
caught by fork tests rather than by review:

- it guarded on `ts != nil`, so a frame carrying `event_timestamp: 0` took the dedup path as
  `Some(0)` and two separate taps collapsed into one dispatch;
- its map was never cleared per connection, so a timestamp held over from the previous link
  swallowed the first genuine gesture after a reconnect.

## What the 260919 log said

**The HealthKit writes are not measurably expensive — but the instrumentation cannot yet prove
it either way.** `writeBack=4s` in the header is an average over `syncs=2`, not a regression from
the earlier 103–396 ms; those were reads-only runs over larger sync counts. More importantly,
`recordWriteBackPhase` wraps only `sync()`, while the main write route
(`writeBackAfterNewData()`, fired on every completed backfill — ~37 in that log) has no
instrumentation at all. **No conclusion about HealthKit-write battery cost is supportable until
that gap is closed.**

**A counter-namespace collision is corrupting two header lines.** `RescoreStats` and
`RetroScanStats` share the `rss.` UserDefaults prefix and collide on `rss.day` and `rss.maxMs`:
whichever rolls first zeroes the other's counters mid-day, and `maxMs=148117` on the retro-scan
line and `longest 148s` on the re-score line are demonstrably the same stored integer printed
twice. At most one is true. **Not yet fixed — it is the first thing to fix next.**

Otherwise: BLE wakes roughly halved (99,247 → 42,724 puffin), nothing is being permanently lost
(every "dropped" counter is a deferral, and abandoned passes deliberately do not advance the
watermark), and the largest attributable cost remains re-score SQL reads.

## Features

**Two Targets widget styles, chosen on the phone.** `NOOPTargetsWidget` keeps its four bars;
`NOOPTargetsRingsWidget` draws the same four targets as a 2×2 of progress rings. One view, one
provider, one snapshot and a style flag — the numbers, colours and accessibility are shared, so
the two cannot disagree.

**The battery icon finally moves.** Both widgets drew a hardcoded `battery.50` beside a live
percentage — a full strap and a flat one wore the same glyph. The banding existed in `TodayView`
but was not reachable from the extension. It moves to `BatteryGlyph` in `StrandiOSShared`, and
`TodayView` delegates to it (verified behaviour-preserving by oracle over 0.0–100.0 in 0.1 steps).
Six steps as requested, which SF Symbols cannot express, so the header draws its own pips.

**The real app mark**, geometry measured out of `icon_1024.png` rather than eyeballed — an earlier
attempt drew the older `docs/assets/logo.svg` pulse trace, which is not what the app wears.

**The Today synthesis flags what is notable.** It used to mandate three sections every day, which
guaranteed the drab summary: three headings to fill whether or not anything happened. It now leads
with real deviations from the wearer's own baselines, trends and watchouts, is told FEWER IS
BETTER, and is explicitly allowed to say a day was unremarkable.

**A download on Recap**, mirroring Trends — but text, not PDF, because the stated destination is
another LLM and a PDF arrives there as pixels.

**The coach summary stops going stale.** The scenePhase handler generated on open, the morning
sync landed seconds later, and nothing regenerated it. The engine now records which `refreshSeq`
each paragraph was written from; both sync-completion paths regenerate when the data has moved.

## What the next log must show

1. **The `rss.` collision fixed first** — until then, treat `maxMs`, `longest`, `runs` and
   `blocked` on those two header lines as unreliable.
2. **Instrument `writeBackAfterNewData()`** and split the write-back divisor from `syncs`, so the
   HealthKit-writes question can actually be answered.
3. Whether `refreshSynthesisIfDataChanged` fires in the morning — a regenerated paragraph should
   follow the first post-window sync, not the app open.
4. Whether the light-pass `served=0` / `reuseOff=1` pattern persists (~14 passes/day re-reading
   ~226k samples for 2 nights is the largest attributable cost that is already measured).

## Verification

Both app targets build. 2405 tests, 2 failures — `SkinTempAbsoluteDisplayTests` and
`SleepCarriedStampTests`, both upstream's own files, both failing identically on a clean v11.8.0
checkout with no fork code present. Widget faces checked by rendering at true point sizes (SE
141pt, iPhone 17 158pt) in typical, widest-value and empty states; nothing clips.
