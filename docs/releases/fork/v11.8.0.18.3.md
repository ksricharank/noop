# 11.8.0.18.3 (build 404)

Two final corrections to the 260919 batch.

## The weekly digest is gone from Trends

Reported as "this weird section that doesn't even change when I select different windows". That was
exactly right, and it was by design: the block had its **own** prev/next week chevrons and
deliberately ignored the range selector.

The first fix attempted was to label the scope on each row — "5 scored days *this week*". That was
the wrong call, and the maintainer said so plainly: *"I don't want some weekly thing independent of
the range selector. plus the day quality shows up in other areas."*

Both halves hold. A second, differently-scoped week view on a page built around a window control is
confusing whatever it is labelled. And `weekInReview`, directly below it, already shows **Day
quality, Charge, Effort and Rest over the selected range** — so the digest was the duplicate, and
it was the one ignoring the control.

Removed with its whole support cast: the week stepper state, its clamp, the anchor-day derivation,
the nav bar, the two score rows and the per-week share button. `TrendsSection.weeklyDigest` goes
with it, so Arrange cannot offer a card that renders nothing.

Two judgement calls inside that removal, both deliberate:

- **`valuesInWeek` survives.** `TrendsScoreSeriesTests` is the only guard on its string-comparison
  range rule, and deleting a tested pure helper to tidy a view trades a real invariant for a
  cosmetic one.
- **`earliestDay` does not.** It existed solely to clamp the week stepper, and dead code compiles
  clean — which is precisely how a lost Coach context menu went unnoticed earlier in this same
  uplift.

## The widget's type

Values 19 → 17pt, mark 27 → 31pt. The values had grown enough to crowd their labels; the mark reads
as the widget's identity and carries the extra size.

## A note on the last four builds

18.0 through 18.3 were one feature batch and three rounds of correction, every round driven by a
screenshot. Three of those rounds turned up a regression caught by a **test** rather than by
review: a dropped total-calories guard, a Markdown surface that silently became plain text, and an
enum case left referenced by its own test.

The pattern is not that the tests were lucky. It is that this fork's UI work has no CI, so the
tests written alongside a change are the only thing standing between a refactor and a silent
behaviour loss. Worth keeping in mind when a change looks too small to need one.
