# 12.0.0.19.37 (build 473) — 261123

One change on `feature/v15-widgets`. FEATURES unchanged; `store-concurrent-reads` re-stacked.

## 1. Pulsing removed, experimental styles capped

Pulsing (effect 52) at ×8 left the strap buzzing through double taps and a disconnect. It stopped
only with Devices › Restart strap… (opcode 29, confirmed on 5.0). A 5/MG has no stop command NOOP can
send (STOP_HAPTICS 122 is 4.0-only).

- The Pulsing style is gone. A stored "pulsing" reads back as Standard.
- Long and Longest are capped at **2** repeats, and Standard keeps 1–8. The cap
  (`StrapBuzzPrefs.cappedLoops`) applies where every 5/MG buzz is built, so in-session cues are held
  to it too, not only the notification count.

## 2. Notifications not buzzing after a background relaunch

"Take a deep breath" this morning: no buzz. The 261123 phone log covers it, and the morning brief and
the 7:30 water reminder: all three were posted, and the log shows **no haptic write at all**.

- Cause: iOS relaunched NOOP at 07:00 (state restoration). `willRestoreState` sets `didBond` and
  `encryptedBond`, then a `didConnect` for that same link cleared `encryptedBond`. The CLIENT_HELLO
  ack couldn't set it again because `didBond` was already true. So the whole relaunched session ran
  with `canBuzz` false, and every automatic buzz was skipped silently. Test buzz never checks that
  flag, which is why it always worked.
- Fix: `didConnect` keeps the bond when it is the restored link and no disconnect ran in between. It
  re-sets it after the identity publish, in the same order the restore path uses. Log:
  `Restored link connected — keeping the bond restoration proved`.
- Any buzz skipped for an unbonded link now logs
  `Buzz skipped (<cue>): strap link not bonded (bonded=… encrypted=…)`.
- The breathe check-in (live and from sync) was the one nudge still on the bare, unacknowledged
  buzz write. It now uses the same acknowledged notification buzz as the rest.

## 3. Counted water spread through the day

"Start at 0 when I wake up, and add evenly to end up at 6 by say 9 pm."

- Automations › Water reminders: **Cups counted for you** (default 6, 0 = off) and **All counted
  by** (default 9:00 pm).
- From 0 at wake (today's main sleep end, or the quiet-hours end until it's scored; the same wake
  target pacing uses, now `Repository.wakeMinuteToday`) it rises evenly. With 7:00 → 21:00 that is
  one cup every 2 h 20 min, the first at 9:20.
- Each sync or screen load logs any cups now due as one ordinary entry. NOOP counts what it added,
  not the day total, so deleting an entry sticks.
- A day the 19.36 build already filled counts as done.
