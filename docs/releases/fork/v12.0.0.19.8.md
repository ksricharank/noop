# 12.0.0.19.8 (build 444) — 261008

Ships everything cut as 19.7 (never pushed), plus an audit fix to 19.7's Charge refresh, the
editable explain-like-I'm-10 voice, and a 06:30 sleep-window default. A main-night Charge branch
(`feature/charge-main-night`) was built for this release and then DROPPED before shipping at the
maintainer's call — see "Not shipped" below.
Read `v12.0.0.19.7.md` for the 261007-2102 log analysis behind the first two Charge changes.

## Charge, two fixes

1. **A trusted partial pass refreshes today's night** (`feature/v15-widgets`, from 19.7). The 260922
   "partial passes never overwrite Charge" rule now keys on the baseline: trusted (≥14 nights) →
   today's row refreshes as a unit; thin → the original rule. Cause: the 06:00 score of 43 stood until
   08:18 while every trusted pass computed the finished night's 50.
2. **Audit fix (new in 19.8):** that refresh rewrote today's daily row, but partial passes still wrote
   no metric series — so today's Rest (`sleep_performance`, a sleep-target and session-ladder input),
   sleep onset, SpO₂ candidate and resting-HR diagnostics kept describing the old night. Today's series
   are now written with the refreshed row (per-(day, key) upsert; no other day touched). One
   `refreshTodayKey` feeds both decisions.
## Not shipped: main-night Charge (maintainer decision, 261008)

`feature/charge-main-night` scored Charge's physiology (HRV, resting HR, respiration, skin temperature)
from the main night only, instead of upstream #525's day-wide pool over every matched block. It was
built, tested (StrandAnalytics 2135/2135 with two re-pins) and deleted unshipped. Consequence: an
evening rest or nap that the detector matches as a sleep block for today can still move today's Charge
(the 261007 20:42–20:52 50 → 51 → 53 → 50 episode), upstream behaviour unchanged.

## Sleep window ends at 06:30 by default

Maintainer decision: the window end belongs just BEFORE a usual wake (the morning then converges on
its own via fix 1), not after it. Default 07:00 → 06:30; NotificationSettingsStore's inline 07:00
fallback for the same key now reads the shared constant. A saved window is unchanged — the maintainer
sets theirs to 06:30 in Settings → "Sleep ends".

## Coach voice: explain-like-I'm-10, editable

19.7's fixed plain-language rider is now an editable prompt (Coach settings → "Plain-language
instructions", shown while the voice toggle is on), defaulting to explain-like-I'm-10 — the age is a
one-word edit. Still applied over every surface prompt override. Text size +1 (cards 13 → 15, chat
15 → 16) as in 19.7.

## Why the Charge preserve rule was safe to relax (for the record)

It existed because partial passes once scored against a baseline folded only from the nights they
scanned (`hrvNValid=2` → the 22↔47 and 31↔63↔30 flips). The 260922 baseline fix removed that cause:
partial passes fold the full window from stored history, and every pass since logs
`hrvNValid=21 trusted`. Re-audited 261008: the day loop's abort gate sits BETWEEN days (a scored night
is always fully read), light passes read streams through the same loop and analyzeDay inputs as full
passes, and the sleep-need / midsleep inputs read stored sessions over the window either way. In the
261007 log, light and full passes computed identical HRV for today all day outside the matched=2 window.
