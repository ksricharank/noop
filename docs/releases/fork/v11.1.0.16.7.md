# 11.1.0.16.7 (build 319)

One fix: the step-source toggle, which **shipped inert in 318**.

Build 318 IS installed, and its water double-tap was confirmed working on the strap ("the water tap
works beautifully"). Everything else in 318 — and in the never-installed 316 and 317 it carried —
stands. The 16.4, 16.5 and 16.6 checklists still apply for anything not yet confirmed.

## The steps toggle did nothing, and could never have worked

Reported from the device: "when I change the toggle, nothing changes in the UI."

`Repository.mergeAppleSteps` read `dailyMetrics(deviceId: "apple-health")`. Those rows do not carry
steps and never will — `HealthKitBridge` constructs them with no `steps:` argument at all (sleep,
resting HR, HRV, SpO2, respiratory rate is the whole list), so the field is nil for every row it
writes. Apple's step count lives in `appleDaily` / `AppleDailyAggregate`, which is precisely why both
Today views already reached for that table separately as their own fallback tier.

So the fold's `guard let steps = row.steps` skipped every row, on every day, for everyone. The
feature was a guaranteed no-op from the moment it was written.

Fixed by reading `store.appleDaily(...)`, still gated on the preference so a strap-preferring install
does not pay for a query it will not use. A day only Apple covers now mints a steps-only row instead
of being skipped — the exact case the preference exists to surface, which the previous code could not
express because it had been handed the wrong row type to begin with.

## Why the tests passed, and what changed about that

This is the part worth recording, because it is the SECOND time this fork has shipped a feature
inert behind green tests — 16.2 did it with the day-quality gate.

The tests fabricated apple-side `DailyMetric` rows WITH steps: a shape the app cannot produce. Eight
passing tests described data that does not exist. A fixture that cannot occur in production proves
nothing about production, and no amount of adding more tests of the same kind would have caught it.

Two guards, neither a restatement of the fix:

  * `mergeAppleSteps` now takes `[AppleDaily]`. Handing it the stepless rows is a COMPILE ERROR
    rather than a silent no-op — verified by reverting the fix, where the test file fails to build
    instead of passing.
  * A test reads `HealthKitBridge` itself and asserts the apple-health `DailyMetric` construction
    still sets no steps, while the aggregate construction does. That checks the premise against the
    code that actually writes the data, rather than against a fixture written from the same wrong
    assumption as the bug.

The general lesson for this fork, now paid for twice: when a feature reads a store, a test that
invents the stored shape is not evidence. Assert against the WRITER, or against the device.

## A correction carried over from 16.6

Recorded again because it is easy to lose: the steps toggle moves the NUMERATOR only.
`DailyTargets.stepsTarget` takes charge and readiness, and neither `ReadinessEngine` nor the recovery
math reads steps, so the target is independent of this preference. An earlier revision of the
HealthKit observer's own comment claimed otherwise; that has been corrected in the code and pinned by
a test.

## What the next install must show

The whole point of this build, and the bar is higher than usual because this feature has already
claimed to work once:

1. **Switching to Apple Health visibly changes the step number** — the Today tile, the steps figure
   in the targets strip, and the day-quality steps component should all move together to the Watch's
   count, within a refresh.
2. **The step TARGET does not change** when the source does.
3. **Switching back** restores the strap's count with no blanked days in Trends.
4. **A day only the Watch recorded** now shows a step count where the strap has no row.

Still unverified from earlier builds: the notification "Add a cup" action, water on the widget faces,
the macOS idle-at-launch change, and whether the model-written notification titles now land (16.4's
two fixes).
