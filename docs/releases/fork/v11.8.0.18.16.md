# 11.8.0.18.16 (build 417)

A guard that closes a real hole, three ledgers that found the actual bug — and a first draft of
these notes that claimed the Charge flip was fixed. It was not. The next morning's log said so,
and 18.17 is the fix. This file is the corrected record.

## What this build shipped

**A baseline-sufficiency guard on recovery.** The 260906 abort gate can stop a full pass at
night N; on a strap-only install those N nights ARE the HRV/RHR baseline, so pass 2 z-scored the
night against a window it never scored. Measured against the shipped scorer: 64 folded from 4
nights, 30 folded from 21, same night. The guard (`partialBaseline = lightPass || wasAbandoned`)
makes a partial pass preserve the stored Charge via the existing `lightPassMerged` path. Correct,
mutation-tested, and — per the 260921-0740 log — not what was flipping the Charge: zero
`kind=abandoned` writes appeared, and the flip happened anyway.

**Three always-on, counts-only ledgers:** `chargeWrite` (every recovery write, with `hrvNValid`
and the pass kind), `chargePublish` (what Charge the widget snapshot carried, from which anchor
day, and whether WidgetKit was asked to reload), `chargeShown` (what the screen drew and from
which `ChargeDisplay` branch, on transitions only). These are what located the real cause within
one export.

## What the ledgers showed

`chargePublish anchor=2026-08-18 (carried) charge=36` — the 36 was **18 August's** Charge. Today's
row was nil at launch because the last build-416 background pass had been abandoned after one
night and had (a) written today with a sub-seed nil and (b) **deleted the other twenty computed
days**, so the carry fell past yesterday all the way to the oldest scored row outside the window.
Separately, `hrvNValid=10` on a 21-night window: every night before 12 September has no
readable R-R. Both are explained and fixed in 18.17.

## Verification

Both app targets compile. 6 new tests pass, mutation-checked; the full macOS suite ran with only
the 4 failures already present on a clean worktree.
